# AI22 evaluation, 2026-10-07: speech recognition and translation

Status: **partial matrix, accepted as the basis for v1 defaults** (by the user's decision
to stop benchmarking and build). The harness, rubric and gates are described in
`docs/implementation/ai-model-evaluation.md`. Raw JSON stays with the data on the model
SSD (`results/2026-10-07/`).

**Hardware:** Apple Silicon Mac on macOS 26, warm runs after Core ML warm-up.
**Data:** FLEURS test (en_us, fr_fr, ar_eg), with 40 offline clips and three ~90 s
streams per language. Translation uses the first 100 FLORES-200 devtest sentences.

**Not measured, because the run stopped early:**
- whisper small, and medium at a 0.5 s step for French and Arabic only partly;
- Apple SpeechTranscriber across the full set (an English/French smoke run only; it has
  no Arabic);
- the full translation matrix (NLLB-600M, TranslateGemma 4B, Apple Translation, and the
  fr→en, ar→en, fr↔ar directions).

## Decisions (v1 defaults)

### Speech recognition: whisper large-v3-turbo q5_0, Core ML encoder, 1 s step, for all three languages

**Why this model:**
- It has the best streaming WER in every language: en 0.084, fr 0.095, ar 0.150.
  Medium has worse Arabic streaming (0.241 to 0.377) and fails the Arabic gate.
- First text appears after speech onset in 0.17–0.86 s (p50), which passes the 1 s gate.
- Streaming RTF is 0.53–0.59 and offline RTF is 0.054–0.060, leaving headroom for
  playback.
- Peak RSS is 880 MB, which passes the 2.5 GB gate.
- **The 0.5 s step is rejected.** Its stream RTF is about 1.0, so it does not keep up.
  It also degrades Arabic WER to 0.318.
- **q8_0 is close but not chosen.** Its Arabic WER is slightly better (0.162 against
  0.150 is within noise) and its lag is a little lower. It costs 290 MB more memory and a
  slower load. It stays as an optional "quality" variant in the manifest.

**Cold start:** the first Core ML load compiles the encoder (31–38 s). Until that compile
finishes, the same GGML weights run on the Metal path. Metal's quality is equivalent
(streaming WER en 0.081, fr 0.101, ar 0.177), and its first text arrives in 0.46–1.13 s.
Captions therefore never wait for the compile.

**Known gate failure: committed lag.** Every candidate fails the committed-lag gate: p95
is 7.3–21.9 s against the 3.5 s gate, and the p50 for turbo is 4.7–5.6 s. This is the
LocalAgreement-2 policy confirming each word over two consecutive decodes. The
Whisper-Streaming paper (Macháček et al., 2023) reports about 3.3 s on its own setup.

Mitigations:
- **In the product:** provisional text is shown immediately, dimmed, and committed text
  replaces it. Only committed text is persisted or translated.
- **Follow-up:** VAD-segmented commits, which end an utterance on silence instead of
  waiting for agreement, and buffer trimming on sentence ends.

The gate stays in the rubric. It is not relaxed.

### Translation: Opus-MT (Marian, ONNX, in-process), one model per direction

**Measured directions:**
- **en→fr:** chrF++ 67.4, BLEU 47.2, p95 298 ms.
- **en→ar:** chrF++ 50.2, BLEU 23.4, p95 328 ms (with the `>>ara<<` target token).

Both pass the 400 ms gate. Peak RSS for en→ar is 692 MB. The en→fr run predates RSS
recording.

**The other directions:**
- **fr→en and ar→en** use the same Opus-MT family. They are unmeasured, and are labelled
  provisional in the manifest until a run confirms them.
- **fr↔ar** has no direct Opus model. It pivots through English, so it takes two hops
  and is expected to exceed the per-segment gate at p95. That is acceptable for
  committed-only, asynchronous translation, but it is flagged.
- **NLLB-600M** would give a direct fr↔ar path. It is non-commercial (CC-BY-NC) and
  unmeasured, so it is not a default.
- **Apple Translation** needs language packs the user installs. It is not a default.

Everything runs on the app's single ONNX Runtime, with no protobuf (see the Phase 7
removal).
